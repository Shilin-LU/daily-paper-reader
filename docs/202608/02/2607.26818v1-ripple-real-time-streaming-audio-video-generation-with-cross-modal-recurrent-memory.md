## 摘要
音视频生成模型达到了令人印象深刻的画质，但存在高延迟问题，不适合实时应用。尽管已经提出了几种流式音视频生成方法，但它们仍然成本高昂，且无法支持长视频生成。为了解决这一问题，我们提出了Ripple——一种具有跨模态循环记忆机制的实时联合音视频生成系统。为了在保持长期上下文的同时实现高效的流式推理，Ripple结合了固定长度的滑窗注意力与特定模态的记忆状态，这些记忆状态持续总结音频和视频上下文。进一步引入跨模态记忆交互以增强音视频同步。为了有效学习这种记忆增强模型，我们设计了一个三阶段训练方案：（1）将双向音视频教师模型适配为具有模拟记忆的块状因果注意力模型，（2）通过端到端蒸馏优化记忆构建和交互流程，以及（3）应用专为流式音视频生成量身定制的在线强化后训练。最终，Ripple在480P分辨率下实现了约28帧每秒的生成速度，比教师模型快得多，同时能够生成长度连贯的长视频。在短视频和长视频基准上的大量实验表明，我们在现有的离线和在线联合音视频生成方法中取得了优越性能。

## Abstract
Audio-video generative models achieve impressive quality but suffer from high latency, making them unsuitable for real-time applications. Although several streaming audio-video generation methods have been proposed, they remain costly and fail to support long-form generation. To address this, we propose \textbf{Ripple}, a real-time joint audio-video generation system with a cross-modal recurrent memory mechanism. To enable efficient streaming inference while preserving long-term context, Ripple combines a fixed-length sliding-window attention with modality-specific memory states that continuously summarize audio and video context. Cross-modal memory interaction is further introduced to enhance audio-visual synchronization. To learn this memory-augmented model effectively, we devise a three-stage training recipe: (1) adapting a bidirectional audio-video teacher to block-wise causal attention with simulated memory, (2) optimizing the memory construction and interaction pipeline through end-to-end distillation, and (3) applying online reinforcement post-training tailored for streaming audio-video generation. As a result, Ripple achieves ~28 FPS at 480P resolution, over faster than the teacher, while capable of coherent long-form generation. Extensive experiments on both short-video and long-video benchmarks demonstrate our superior performance over existing offline and online joint audio-video generation methods.

## 1. 核心问题与研究动机

- 现有音视频生成模型（如 LTX-2.3、Wan、HunyuanVideo 等）通常采用**离线双向生成**范式，需先看到完整时间上下文才能输出，推理延迟极高，无法满足实时交互场景。
- 近期出现的流式方法（如 OmniForcing、Hallo-Live）虽通过在**双流架构**上进行因果蒸馏实现了流式生成，但仍存在两大缺陷：
  - 依赖**不断增长的 KV cache**，上下文越长计算成本越高，推理延迟持续上升；
  - 仅支持约 5 秒的短视频生成，**难以进行长时程（minute-level）连贯生成**。
- 论文由此提出核心问题：如何实现**实时、高效、可支持长时生成**的联合音视频流式生成模型？

论文的核心含义是：在保持实时推理效率的同时，用一套紧凑的**跨模态循环记忆**机制来弥补滑动窗口所损失的长期上下文，从而在流式约束下实现高质量、长时程、且音视频同步的联合生成。

## 2. 方法论：Ripple 的技术方案

### 2.1 总体设计思想

Ripple 以**因果、逐块（block-by-block）生成**的方式联合合成音频和视频。为了在流式生成中保持长期依赖又不增加计算成本，它采用“**固定长度滑动窗口注意力 + 跨模态循环记忆**”相结合的策略。注意力上下文由三部分组成：
1. **首块 KV cache（sink cache）**——提供全局锚点，保持场景和身份；
2. **长期跨模态记忆**——以紧凑向量摘要窗口覆盖之外的历史信息；
3. **上一块 KV cache**——保留最近上下文。

### 2.2 跨模态循环记忆机制

- **模态特定记忆构建（Modality-Specific Memory Construction）**
  - 对视频（v）和音频（a）分别维护一组可学习记忆查询 \(Q_m\)，当某个块的 KV 被滑出窗口后，利用这些记忆查询对“被逐出的 KV”进行注意力读取，得到记忆读出 \(M_{out}\)：
    \[
    M_{out}^m = \mathrm{softmax}\left(\frac{\hat{Q}_m \hat{K}_m^\top}{\sqrt{d_m}}\right) V_{evict}^m
    \]
  - 记忆状态通过**指数移动平均（EMA）**更新，并用 L2 归一化保持稳定：
    \[
    M_m \leftarrow \mathrm{norm}(\alpha M_m + (1-\alpha)M_{out}^m)
    \]
  - 记忆查询使用零位置 RoPE，使记忆具备位置无关性；被逐出的 key 保留原始位置编码，可保留时间结构。

- **跨模态记忆交互（Cross-Modal Memory Interaction）**
  - 音频和视频记忆处于不同特征空间，先在共享维度上投影（Q/K/V），然后进行**交叉注意力**，以残差方式更新：
    \[
    \tilde{M}_v = M_v + \mathrm{softmax}\left(\frac{Q_v K_a^\top}{\sqrt{d_c}}\right)V_a
    \]
    \[
    \tilde{M}_a = M_a + \mathrm{softmax}\left(\frac{Q_a K_v^\top}{\sqrt{d_c}}\right)V_v
    \]
  - 交互后的记忆经投影后作为长期记忆 KV 对注入 Transformer 自注意力，增强音视频同步与长期一致性。

### 2.3 三阶段训练流程

1. **Stage 1：记忆增强的块因果适配**
   - 将双向教师（LTX-2.3）的注意力替换为“sink + 模拟内存 + 滑动窗口”的块因果注意力；
   - 通过**推理 rollout** 得到中间 KV 来模拟长期记忆，逐步让模型适应新的因果注意力模式；
   - 使用 flow matching 目标向教师 ODE 轨迹学习，为后续蒸馏提供初始化。

2. **Stage 2：跨模态记忆强制蒸馏（Memory-Forcing Training）**
   - 在阶段 1 基础上，端到端优化“构建-交互”记忆管线；
   - 使用 **DMD（Distribution Matching Distillation）** 将双向教师蒸馏为 4 步学生模型；
   - 训练中记忆状态持续更新、跨模态交互持续发生，让学生学会利用累积的跨模态上下文。

3. **Stage 3：在线扩散强化后训练（Online RL Post-training）**
   - 采用 **GRPO** 框架，每个 GPU rank 用一个不同种子生成双流 rollout，reward 跨 rank 聚合，计算组内相对优势；
   - 组合奖励：音频-视频同步（Synchformer）、语音对齐（ASR 的 WER/CER）、视频质量（HPS）、音频质量（DNSMOS）；
   - 采用**渐进式奖励调度**：先优化语音对齐与同步，再转向感知质量（保留少量对齐奖励）；
   - 损失为优势加权后的扩散转移 log 概率，并加入 KL 正则惩罚，防止 policy 偏离参考模型：
    \[
    L_{RL} = -\mathbb{E}_{\tau}\left[ A_i \sum_t \log p_\theta(x_{t-1}|x_t) \right] + \beta D_{KL}(\pi_\theta \| \pi_{ref})
    \]

### 2.4 流式推理

- 生成时逐块输出、每块生成后立即输出，支持增量流式接收；
- 固定大小 KV cache + 滚动缓存（rolling cache）策略，RoPE 位置超过训练长度时进行截断；
- 切换 prompt 时重置记忆状态，避免上下文串扰。从而支持分钟级长视频生成且每块计算成本恒定。

  - RL 两阶段奖励调度和 KL 惩罚对稳定训练和最终质量均至关重要。

## 7. 优点与亮点

1. **问题定位精准**：直击现有流式音视频方法“KV cache 无限增长 + 无法长时生成”的痛点。
2. **新颖的记忆机制**：提出“模态特定循环记忆 + 跨模态交互”的紧凑记忆方案，在固定开销下保留长期上下文，设计优雅（EMA 更新 + L2 归一化 + 零位置 RoPE 查询）。
3. **三阶段训练范式的创新**：将“因果注意力适配 → 记忆强制蒸馏 → 在线强化”结合起来，有效弥合双向教师与流式学生之间的差距，且首次将 GRPO 强化学习应用于流式音视频生成。
4. **效率与质量兼顾**：在达到实时速度的同时，长时一致性甚至优于教师，满足实际应用需求。
5. **实验体系较完整**：同时提供短视频标准基准、自建长视频基准、消融、用户研究、开放场景泛化和音频/唇形定性分析。

## 8. 不足与局限性

1. **动作多样性受限**：首块 sink cache 有利于保持身份和场景，但也导致“时间锚定”效应，限制了后续生成块的动作幅度和动态变化（论文在 Limitations 中明确承认）。
2. **长时性能仍有损失**：30 秒长视频中语音对齐和音视频同步略低于教师，说明记忆压缩在长距离跨模态对齐上仍有损失。
3. **训练数据偏见**：训练以人类中心内容为主，尽管补充了开放场景泛化示例，但整体泛化能力可能仍偏向 talking-head / 人物场景。
4. **长视频基准未与竞品直接对比**：因 OmniForcing 和 Hallo-Live 无法生成长视频，长视频比较仅限同源教师，削弱了对“在线方法普遍无法长时生成”的公平性佐证。
5. **强化学习的奖励设计依赖外部模型**：Synchformer、ASR、DNSMOS、HPS 并非完美度量，可能引入指标偏差；且论文未说明 reward 之间权重和调度选择的敏感性分析。
6. **算力成本高**：32 张 H100 的资源和 3M 数据量门槛较高，可复现性受限；论文没有报告详细的每阶段训练时间。
7. **伦理风险**：高保真实时音视频生成可能被用于身份冒充、深伪内容等恶意用途，论文虽声明了学术目的和防护建议，但未提出系统性缓解方案。
