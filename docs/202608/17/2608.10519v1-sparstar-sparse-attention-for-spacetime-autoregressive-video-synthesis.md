## 摘要
InfinityStar通过一系列图像和片段金字塔将视觉自回归生成扩展到视频。然而，其变化的尺度和跨片段上下文使得后期尺度的注意力成本高昂，并且使得从扩散或图像VAR模型中复用的稀疏模式变得不可靠。我们引入了SparSTAR，一种针对此场景的免训练块稀疏注意力方法。在每个高代价尺度和注意力头处，SparSTAR根据当前查询和键激活对连续键块进行评分，保留所需的条件上下文，并通过仅前向的稀疏路径执行选定的块。我们分析了片段内的跨尺度一致性、跨片段边界的模式持久性，以及随着复用跨度扩展到越来越远的尺度时质量下降的情况。在这些分析中，重要的键块会发生偏移，表明在每个目标尺度上重新计算块选择比复用转移掩码更可靠。在720p文本到视频和图像到视频生成中，SparSTAR保留了每个token和细化尺度，同时提供了约1.6倍的端到端加速，并保持了接近稠密InfinityStar的VBench和成对输出重建保真度。

## Abstract
InfinityStar extends visual autoregressive generation to video through a sequence of image and clip pyramids. Its changing scale and cross-clip context, however, leave late-scale attention costly and make sparse patterns reused from diffusion or image VAR models unreliable. We introduce SparSTAR, a training-free block-sparse attention method tailored to this setting. At each expensive scale and attention head, SparSTAR scores contiguous key blocks from the current query and key activations, retains required conditioning context, and executes the selected blocks through a forward-only sparse path. We analyze cross-scale consistency within a clip, pattern persistence across clip boundaries, and quality degradation as reuse spans increasingly distant scales. Across these analyses, important key blocks shift, showing that recomputing block selection at each target scale is more reliable than reusing a transferred mask. On 720p text-to-video and image-to-video generation, SparSTAR preserves every token and refinement scale while providing about a 1.6x end-to-end speedup and maintaining VBench and paired-output reconstruction fidelity close to dense InfinityStar.

## 1. 核心问题与整体含义（研究动机与背景）

- 视频生成模型主要分为扩散模型与视觉自回归（VAR）模型。InfinityStar 采用**时空自回归（STAR）建模**，先生成图像金字塔，再按序生成片段（clip）金字塔，通过“下一尺度预测”逐步细化视觉token。
- 尽管 STAR 框架避免了扩散模型的重复去噪，但**注意力仍是主要瓶颈**：随着分辨率提高，KV 规模迅速膨胀；InfinityStar 虽用 Spacetime Sparse Attention（SSA）裁剪历史上下文，但每个 clip 的**当前尺度仍需稠密地注意前一片段末尺度、文本条件与当前尺度token**。在 720p 下，仅最后尺度就包含 72,000 个token，注意力成本极高。
- 已有训练免稀疏注意力方法多面向**固定分辨率的扩散网格**，难以直接迁移到 STAR 视频生成中；而图像 VAR 中的跨尺度模式复用（如 SparVAR）在 STAR 视频生成中因跨 clip 上下文变化而变得不可靠。
- 本文通过系统分析发现：在 InfinityStar 中，**注意力模式无法可靠地在尺度间或 clip 边界间转移**，复用旧模式会造成大量注意力质量损失。基于此提出 **SparSTAR**，一种免训练的动态块稀疏注意力方法，在保留全部 token 与细化尺度的前提下，大幅降低后期尺度注意力开销。

## 2. 方法论：核心思想、关键技术细节

- **核心思想**：与其复用早期尺度或早期 clip 的稀疏掩码，不如在每个高开销尺度和注意力头上，基于**当前 query 与 key 激活**动态重算块选择，形成逐尺度、逐头的稀疏模式。
- **技术细节**：
  - **原始顺序块划分**：将 query 和 key 序列按注意力 kernel 顺序划分为连续块，块大小 `b=128`，不按语义边界对齐，保留光栅顺序。
  - **聚合 Query–Key 块分数**：对每个 query 块和 key 块，先计算块内 token 向量的均值 `¯q_i`、`¯k_j`，再计算它们的缩放点积 `S_ij = τ ¯q_i^T ¯k_j`（`τ = D^{-1/2}`）。由于双线性，这等价于两完整块间所有 token 对预 softmax 兼容性的平均，可作为排名分数；参数自由，且把 token 级计算量降低约 `b² = 16,384` 倍。
  - **Clip 相关保留与可选块集合**：
    - Clip 1：文本块和最终图像金字塔块始终稠密，只对当前尺度块进行选择；
    - Clip ≥2：仅文本块始终稠密，前一片段最终尺度块与当前尺度块在同一预算下联合排名。
  - **尺度级密度调度**：按 query 长度索引密度，采用递减调度（后续尺度有更大稀疏度），720p 下四个稀疏化尺度 `s26–s29` 的密度为 `(0.625, 0.1875, 0.1875, 0.09375)`；最终尺度占稀疏化注意力成本的 74.6%，密度最低。
  - **前向 only 稀疏执行**：基于 FlexAttention 实现称为 **FastFlex** 的路径，只构造前向所需的 `kv_num_blocks` 与 `kv_indices`，省略反向字段，降低掩码构建开销。选择与掩码构建开销在端到端中不足 1.7%。
  - **保持完整性**：不修改权重，不跳过尺度和 token，不压缩 KV cache，只移除部分注意力连接。

## 6. 主要结论与发现

- InfinityStar 中，跨尺度或跨 clip 复用稀疏掩码会导致**显著注意力质量下降**（平均 35.6% 的注意力质量损失，甚至低于简单滑窗）；而逐尺度重算块选择平均仅比 token 级上界低 4.64%。
- 跨 clip 边界时，前一个 clip 末尺度的选择模式仅有部分有效性：在 15% 参考预算下，重算可保留 85% 注意力质量，而复用只保留 56%。
- 随着复用尺度距离增加，质量下降明显增加：每尺度更新模式比单次迁移提高 PSNR 1.73 dB，仅增加 0.30s 延迟，接近稠密上界。
- SparSTAR 在 720p T2V/I2V 上获得 **约 1.60×–1.62× 端到端加速**；稀疏算子比 FlashAttention-2 快 7.08×；VBench 分数与稠密 InfinityStar 仅差 0.04（T2V）和 0.08（I2V）分，重建保真度显著优于已发布的 token 缩减基线。
- 与 Guidance-off（跳过无分类器引导无条件分支）结合可达到 2.50× 加速且质量损失更小；480p 10秒长视频上也可获得 1.31×–1.36× 加速，VBench 降低不超过约 0.9 分。

## 7. 优点

- **免训练、即插即用**：不修改权重、不重训模型，可直接用于现有 InfinityStar 推理管线。
- **保留全部 token 与细化尺度**：与其他 token 剪枝或尺度跳过方法正交，对生成过程扰动更小。
- **动态逐尺度选择**：基于当前 query/key 的聚合块分数构建掩码，避免了跨尺度/跨 clip 模式不可靠问题，原理上更稳健。
- **分析驱动设计**：论文对跨尺度一致性、跨 clip 持久性、尺度距离影响做了系统性量化分析，为方法设计提供了实证依据，不只是“调参式”加速。
- **工程实现高效**：通过前向 only FlexAttention 路径，选择与掩码构建开销极小（端到端 <1.7%）；块划分与核执行对齐，保持 tiled 执行粒度。
- **评估较全面**：覆盖 T2V/I2V、480p/720p、5秒/10秒、重建指标与 VBench 十六维全套件，并包含细粒度消融与置信区间。

## 8. 不足与局限

- **基线公平性受限**：FastSTAR、SparseVAR、FastVAR、ToMe 的结果引用自 FastSTAR 论文，硬件（H100 80GB vs H100 NVL）和评估子集与本文不一致，速度对比并非严格同条件。论文对此有明确说明，但在解读对比时仍需谨慎。
- **模型与场景覆盖面有限**：仅在 InfinityStar 8B 上验证；未测试其他视频 VAR 模型、不同参数量或更高/更低分辨率；多 clip 长视频只验证了 480p 10秒（双 clip），没有更长的多 clip 测试。
- **固定密度调度**：密度值（如 0.625/0.1875/0.09375）对所有 prompt 固定，缺乏自适应调整；虽验证递减调度的优越性，但未讨论根据内容动态调整预算的可能性。
- **块大小受限于 kernel**：默认块大小 128 是因 FlexAttention 在现有 PyTorch/Triton 版本下没有小于 128 的有效配置；32/64 只能走纯张量回退，延迟高达 180.9s/117.6s；块大小对质量的影响未在更小尺度上充分验证。
- **重建指标与 token 缩减方法的可比性问题**：本文强调“保留每个 token”相比剪枝更保真，但推理开销上与 FastSTAR 等 token 跳过方法存在本质差异，论文只做了“上下文性”对比，未在同一框架内实现这些方法。

- **长期时间一致性问题未充分探讨**：尽管多 clip 实验显示 VBench 下降很小，但跨 clip 的累积误差或稀疏模式对时序一致性的长期影响尚不明确，论文在结论中也将其列为未来工作。
